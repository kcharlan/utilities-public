# Architecture

`src/main.c` parses arguments through `src/cli/args.c`, then delegates to
`src/cli/run.c`. The release is a C17 executable; it does not invoke tests
or Python at runtime.

The pipeline is parse → scan/cache → metadata/corpus/workspaces →
catalog/priority/pricing → payload/page:

| Modules | Role |
| --- | --- |
| `src/parse/`, `src/model/` | Stream JSONL into log records, turns, messages, tools, links and usage observations. |
| `src/scan/` (including `logname.c`), `src/cache/` | Classify plain/compressed log names, discover logs, reuse or reparse native cache entries, stage and commit cache updates. |
| `src/claude/` | Inspect source presence read-only, enumerate resolved search roots with provenance/completeness, parse Claude prompts/turns/tools, and insert provider-tagged sessions. |
| `src/meta/` | Load Codex metadata through read-only SQLite connections. |
| `src/acct/` | Track token totals, classify rollouts and resolve inherited fork baselines. |
| `src/corpus/` | Assemble sessions, titles/status, subagent relationships and workspace aliases. |
| `src/price/` | Fetch/cache catalog, validate and record history, retain priority evidence, compose usage and dated costs. |
| `src/out/` | Serialize payload and embed it in the offline page. |
| `src/cli/`, `src/util/` | Coordinate lifecycle, progress, browser/summary, atomic I/O, events, Unicode and stable sort. |

Catalog work starts before scanning and joins before pricing. The CLI reads
ledger state and detects edits before appending newly observed rates; this
does not eliminate the concurrent read/replace race. Rendering precedes
cache commit. Cleanup joins catalog work before freeing shared resources.

The CLI resolves runtime and provider paths and inspects Claude history
before runtime initialization. Absent Codex supplies empty scan, metadata
and priority owners without opening its cache. Claude records have their
own arenas and never occupy Codex `LogRecord` fields. After Codex subagent
linking, `claude_corpus_add` checks canonical filename identities before
insertion; workspace resolution then handles both providers. Exact primary
record aliases are indexed separately, including collision-skipped records.
Codex composition explicitly skips Claude records and initializes their
empty usage summaries. The schema stays 1 with additive provider/source
fields. Rendering still precedes Codex cache commit; unopened caches are
safe to destroy. Claude usage, pricing, graph metadata, persistent retention,
source switching and history-session creation follow in later work.

`tools/embed.pl` embeds `assets/` into build-generated C. Page shell, CSS,
JavaScript, Martian Mono font subsets and their notice, public curated rate
seeds, and Unicode 17 pricing-property ranges ship in the executable.
Unicode 16 normalization/casing tables are committed in `src/gen/` and are
not regenerated by make. yyjson 0.13.0 is vendored in `vendor/yyjson/`;
the zstd 1.5.7 decompression-only sources are vendored in `vendor/zstd/`.
Plain reads and streaming decompression feed the same line splitter.
Compressed logs retain their on-disk path, size, mtime and tail fingerprint
as cache keys; the native cache format remains `native:1:3`.
Production includes retain minimal `src/testing/` support headers; release
test hooks are inactive unless compiled with `COLOPHON_TESTING`.

The fresh test harness independently checks synthetic behavior and retained
C units. The original captured-corpus parity/performance machinery is not
part of this project. See [development](development.md) for its validation
boundary and [third-party notices](../THIRD_PARTY.md) for provenance.

## Usage accounting rules

Long-context thresholds follow CodexBar `v0.74.1` (commit `7c08c0ae7`).
For a catalog model with `context_over_200k`, select the first positive
`context` tier whose rate presence and values match that lane. A non-null
`tier` on the lane itself prevents a match. Fall back to the documented
bundled threshold, then 200,000. Without that lane (or without a catalog
model), retain the bundled threshold. Decode every tier strictly, including
entries after a match; malformed tiers reject the model. Corrected curated
history uses 272,000 in existing entries so earlier usage is repriced rather
than receiving only a newly dated catalog correction.

Remaining differences from `v0.74.1`:

- Native reads `.jsonl.zst` rollouts. Upstream `v0.74.1` and the `main`
  snapshot at `052ded413` accept only `.jsonl`, omitting compressed history.
- Bundled threshold lookup uses the normalized requested model; upstream uses
  the normalized catalog id (`ModelsDevPricing.swift` L246–247 and
  `CostUsagePricing.swift` L65–67). Targets normally agree; native retains one
  bundled-row lookup.
- Ledger-record model selection remains native `model_at` in
  `src/price/compose.c`; upstream `handleRequestLedger` selects differently
  (`CostUsageScanner.swift` L4332–4336). This is outside this alignment's scope.
- Native has no ledger running-counted-total overflow guard; upstream does
  (`CostUsageScanner.swift` L4290–4297). This is outside this alignment's scope
  and separate from per-request numeric validation.
- Native does not port `rememberMirroredLegacyPricingKey`
  (`CostUsageScanner.swift` L4355), `ledgerLegacyPricingKeys` (L361, L4141), or
  `CostUsageScanner+TurnPerformance.swift`. Changed logs reparse from the
  beginning; incremental and turn-performance machinery is outside scope.
- Existing adaptations retain the [Explicit adaptations and approved
  differences table](token_rules.md#explicit-adaptations-and-approved-differences),
  except where a later alignment rule replaces an item. Per-request mirror
  pairing below replaces the per-turn primary rule in Spec §15 difference 1.

Prior Python releases used a 200,000 catalog fallback that could append
conflicting entries to a shared ledger. Use separate runtime homes when
running historical releases; retirement does not migrate private ledgers.

Request-ledger acceptance follows CodexBar `v0.74.1`: require a nonempty
trimmed string thread id matching the NFC session identity. An optional
session id must be a nonempty trimmed string matching the file's trimmed
`session_meta.payload.session_id`, or the session identity when absent/blank.
Foreign ownership is silently skipped. Require a nonempty trimmed response
id, a valid timestamp, integral nonnegative input/output counts, and a thread
total covering input, cached input and output. Optional cached/reasoning counts
default to zero only when absent; reject other types, fractions, nonfinite
values, values whose double representation reaches 2^63, cached > input,
reasoning > output, and input + output overflow. Invalid owned records produce
one aggregate `usage_record_rejected` event. Valid responses deduplicate by NFC
trimmed response id. Keep a turn total only when valid and covering usage.
Ledger cached input uses `cached_input_tokens` only; snapshot rows retain their
existing cache-read alias rule.

Turn identifiers select the first nonempty string `turn_id`, `turnId`, `id`
from payload, then info. A ledger without an explicit turn takes the latest
preceding `task_started` turn in the same file, then the latest nonempty
`turn_context` turn. A started event without a turn clears the started fallback;
blank or truncated contexts leave the active context unchanged. Native cache
format `native:1:3` retains request session ids, ledger totals, context turns and
thread-priority observations.

Snapshots are excluded per request, rather than for every request in a ledgered
turn. Pair accepted ledger records with row-producing `token_count` snapshots
chronologically. Each record claims at most one snapshot. Exact matching uses
the canonical mirror turn, usage including reasoning, timestamp text, and an
absent snapshot total or one matching the ledger thread/turn total. It can cross
boundaries against already observed counterparts. Future exact candidates never
reserve a ledger away from an earlier accepted adjacent match.
An already-owned snapshot for another response preserves the current pending
record instead of claiming it. Ownership uses canonical response identities
and shared mirror-key generation; repeated aliases do not become new partners
(`beginLegacyObservation`, `CostUsageScanner.swift` L428–445).

Adjacent counter aliases use equal turn/usage and thread total; timestamp
aliases use equal turn/usage and timestamp text. Near matches require a nonempty
equal turn, equal input/cached/output (ignoring reasoning), an original record,
timestamps within 5,000 ms and no intervening advance on the later side. Delayed
matches require a snapshot after the record in line order and time, with exact
counter advances on both sides. Advances compare each side's totals against
the preceding total of its own kind: equal to usage is exact, any component
exceeding usage is intervening, otherwise bounded; missing totals/history are
unknown. Every task start, context (including truncation), bare row and repeated
same-session metadata clears adjacency. Repeated metadata resets both histories.
Ledger counter history advances only on originals. Replay detection is per file;
response counting remains session-wide across copies.

A session-wide alias set collects paired snapshot keys and every accepted
record's thread-total, absent-total and valid turn-total keys, including replay
records. Snapshot keys use session, mirror turn, usage including reasoning,
total and timestamp text. Snapshots without last usage also contribute an
observation key with empty usage fields. Either key suppresses mirrored rows
across copies in both scan orders. Unresolved fork baselines contribute no
session aliases. Existing identical-row de-duplication remains in place.

Deliberate pairing differences from CodexBar `v0.74.1`:

- Only snapshots producing accounting rows participate. Other snapshots leave
  pending pairs intact; upstream handles them in `handleTokenCount`
  (`CostUsageScanner.swift` L4603–4632, L4812–4813) and
  `beginLegacyObservation` (L428–437).
- Snapshot history advances when unpaired at observation time or paired with
  the immediately pending original record, rather than all upstream
  `rememberLegacyCounter` conditions (L4633, L4704).
- A repeated response in the same file pairs only exactly or by counter/time
  alias; upstream's replay handling is in `handleRequestLedger` (L4253–4263).
- Record model selection, running-total overflow and retained mirror pricing
  remain the separate out-of-scope differences listed above. In particular,
  native keeps alias keys for records upstream's running-total guard may reject
  (L4290–4299); it does not port retained legacy pricing or turn performance.

Cross-copy aliases follow `reconcileCodexRequestMirrors` in
`CostUsageScanner+RequestIdentity.swift` L58–112. Chronological pairing follows
`beginLegacyObservation`, `handleRequestLedger` and `handleTokenCount`; the
implementation deliberately corrects the proposed whole-file exact reservation
algorithm, which could double-count an earlier near mirror.

Thread-settings priority follows CodexBar `v0.74.1`
(`CostUsageScanner.swift` L3778–3784, L4900–4912, L4404–4421). A valid-timestamp
`thread_settings_applied` event enables thread priority only when its trimmed
string `thread_settings.service_tier` equals `priority`; missing, non-string or
other values disable it. The setting persists until replaced, including across
resumes. Each `task_started` records the setting for its turn, using the empty
id when absent. Every appended record, snapshot or bare usage unit checks the
latest preceding start for its turn in the same file. Resuming the same turn
under a different setting changes later rows without changing earlier rows.
Turnless units check the empty id. Trace-database and sticky priority evidence
still apply; thread settings supply the priority tier without a trace entry.
