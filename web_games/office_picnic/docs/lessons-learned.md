# Lessons learned

- Measure released descent, full-speed pull-up and stall response before laying out crossings. A steady glide ratio alone does not establish a safe receiving roof: record entry speed/pitch/height, roof bounds, and collision-inclusive clearance separately.
- Air columns need bounded heights. Unbounded lift carried the bot into overhead platforms despite safe horizontal gap lengths.
- Broad weaker thermals need enough width to regain height before the pull-up stripe. Test energy recovery through the whole district, not isolated gaps alone.
- A corridor that clears with release alone makes the core input unnecessary. A no-input regression guards the later districts' need for a pull-up.
- Use separate vertical framing on portrait screens; equal x/y scale with long horizontal lookahead left the plane at the bottom of a tall phone screen. Keep warning distance and readable vertical space.
- Stalled-and-held behavior must be checked inside lift, not only in still air. Otherwise the player can gain height despite the intended energy constraint.
- Best times need an in-memory fallback. Reloading unavailable storage at every finish discards the best result between replays.
- Multiple tabs can hold stale snapshots: merge session and stored best times before every write, update only the preference the player changed, and compare finish feedback with the merged prior best while keeping the active tab's settings for replay.
- Landing is a real simulation state: smoothly descend from the actual approach position to the bowl before freezing results. Substituting the bowl coordinate only in the renderer creates a visible teleport.
- Test district feature coverage explicitly. A clamped feature index introduced new lift types but silently dropped AC lift from every later district; use an authored teaching-first cycle that covers all prior types.
- Version best-time storage when route length/geometry changes, so old development runs do not compete with the final course.
- A successful bot route is not evidence of engaging play. The first user playthrough found that early districts permitted passive gliding and every hazard occupied an overhead band. Future difficulty proofs must also demonstrate that early maneuvers and vertical hazard avoidance are necessary, while preserving successful perturbed routes.
- Air-feature presentation must match its physical effect at flight height. A small rooftop vent ellipse plus a 12–18 m/s continuously positive lift cycle made the pulse hard to distinguish from steady AC. A meaningful pulse needs a visible column and a meaningful change in the plane's response.
- Check obvious alternative policies, not just the preferred pilot. A 185m cruising test missed a reachable 230m bypass above the suspended frame. The visible suspension now extends beyond the measured reachable height, and multiple high targets are tested.
- Warning lead in seconds must also allow the required maneuver. The washer's old cue arrived well before collision but too late to descend from normal cruise; use the same preparation distance for the audio/notice, HUD, offscreen marker and reference pilot, then simulate a delayed response at that cue.
- Reject nullable warning timestamps before subtracting them. JavaScript coerces null to zero, letting an absent warning look like a large valid lead time.
- Test a single early input followed by coasting. Weaker lift and two hazard types still left that route through the first district until receiving roofs required rebuilding height after the dive.
- Guidance should describe the next useful action: release when speed is low or height is sufficient, rebuild in lift, and warn about raised receiving roofs. A permanent “hold” hint can teach overclimbing or holding into stall.
- A nose-down animation is not proof of a usable dive. Test actual net descent and speed recovery in the strongest steady lift, from both level and nose-up approaches; remeasure and shorten gaps after changing dive pitch.
- Separate the environmental force, pilot action and observed motion in the HUD. Upward push can coexist with descent; pitching up still spends airspeed. Tailwind with an upward component must disclose both effects.
- Sprite minimum sizes can detach art from collision and cable anchors on portrait cameras. Test actual draw calls against projected collision bounds at multiple aspect ratios, then inspect the result visually.
- Deployment recovery must read a complete saved managed inventory independently of current source edits. Changed-file-only snapshots can mix releases when restoring an older backup. Rollback preserves prior recovery history; only forward deployment prunes it. Existing server directory routes open the file browser, so game links must include `index.html`.
- Validate diagnostic CLI options before running samples: a missing tier must not silently select the default, and reduced samples must not be presented as passing acceptance. Replay validation should check JSON field types and values without depending on object property order.
- A squeeze is one encounter with two collision bodies. Key its warning by the pair, but retain each moving body's own arrival and clearance in proof; the visible label also belongs to the shared window rather than both sprites.
- Validate stored tier IDs as strings before property lookup: JavaScript coerces an array such as `["rush"]` into a valid property key.
- Carry an encounter's identity through every consumer of an emitted warning. Test both members' actual trigger thresholds and a respawn, and use the same live moving geometry for the warning and its marker.
- A warning effect must keep the emitted encounter key even when a different hazard is the nearest marker. Effects also need a bounded presentation clock after the simulation finishes; otherwise landing and best cues never expire.
- A squeeze key identifies a pair, not one collision body. Derive its warning cue and marker from the live shared passage, and exercise an actual emitted warning so a lookup cannot silently highlight just the first body.
- A storage migration needs a best-effort write as well as a readable in-memory result. Keep the old key intact and exercise a denied write separately from successful persistence.
- Transient HUD feedback keyed to a simulation clock must reset with that clock: a Nonstop restart resets world ticks, so clear the previous throw's reward message on respawn.
- Validate authored pickup coverage before pricing the generated world: placements that lack a matching hazard are skipped during world construction and otherwise disappear from every pricing gate.
- Before an explicit CLI exit, wait for queued stdout writes: a delayed pipe reader can otherwise receive truncated JSON even when the process exits successfully.
- A quiet Nonstop restart must rebase a visible impact notice's remaining lifetime when world ticks reset. Keeping the old deadline prolongs it into the new throw; hiding it immediately loses the intended feedback. Exercise the real respawn and expiry boundary.
- Checkpoint placement must account for the entire moving hazard footprint before saving a respawn position. Prove the next crossing at multiple hazard phases and test both held and released inputs immediately after respawn.
- Simulated pilots cache observation error for a hazard. With rooftop retries that context may never change, producing hundreds of identical failed attempts; resample the observation after an impact while preserving learned margins so a new attempt can adapt.
- A rooftop just before a district boundary can remain the active checkpoint after entering the next district. Restore the checkpoint's district with the plane so re-entry emits district guidance again, while the hazard clock continues.
- When a new air feature must follow a safe introduction, test the whole pilot family after removing the entire column, including its wind. An initial raised-roof layout admitted slower pilots without the feature; a later flock after the familiar washer made the dependency measurable while leaving the first encounters familiar.
- Course calibration must cover tier timing and adjacent encounters as well as a single clean route. Later-flock widths and heights that worked in Casual collided with moving hazards or squeezes in Overtime; varying both the flock geometry and squeeze center recovered all perturbed district trials.
- A warning can arrive before the district containing its hazard. Keep the early warning actionable and introduce the new tier element when the player enters its district; a respawn should not repeat the introduction. Attribute teaching-crossing crashes by logged position, including impacts whose gap label is unknown.
- A first-sighting notice must have one trigger. Introducing a squeeze at district entry and again at its later warning duplicated the same banner on clean flights; test complete routes and retries as well as individual event handlers.

## 2026-11-09 — Measuring optional wind lanes

Judge a lane from paired checkpoint runs at the same hazard-clock offsets, including time spent inside its band. A whole-flight time comparison can change with moving-hazard phase even when neither pilot enters the lane. Keep wind-zone reporting separate from the lift-column source: otherwise a lane over a vent suppresses lift-entry and vent feedback. With the 8 m/s Casual lanes, the two median savings were 7.12 s and 5.07 s, with blind occupancy 1.82 s and 0.20 s. A candidate Overtime lane passed the paired study but failed the unchanged route proof, so it was not retained.

## 2026-11-09 — Timing and pilot studies

A delayed-input window measured from a checkpoint can miss height-judgment difficulty and can favor a layout that traps arriving pilots. Use those windows for fairness floors and compare them with complete-flight crash distributions. A lane can also change the hazard clock and pickup approach: verify the paired lane, actual-entry continuation, full pilot bands and pickup pricing together after each final course adjustment.

- A notice deadline can outlive the control phase it describes and obscure the landing close-up. Exercise the actual presentation transition, including the DOM notice, at narrow landscape sizes and both motion settings.
- Nearby air columns can place their labels at the same screen height on portrait displays. Lay out labels against the other labels in the frame and retain every cue; check the resulting bounds at narrow sizes.
- Air guidance must combine the forces at the plane with directions to nearby lanes; an authored headwind can overlap the horizontal span of an out-of-reach tailwind. Fingerprints must include shared course geometry as well as tier and physics configuration. Trigger landing feedback while its canvas remains visible, and exercise the real transition in both motion settings.

- A landing needs a reachable approach as well as a continuous animation. Test release and delayed release from the final moving hazard across speeds and tiers, check the path slope, and give an overhead hold its own slower descent.
- A floor trigger can fire beside the bowl, leaving too little horizontal distance for a shallow glide. Test late releases and switch that case to a flutter while preserving the floor trigger and capture ordering. Frame both table and plane throughout the approach, including the first reduced-motion frame.

- A distance cue alone does not guarantee enough decision time at different flight speeds. Measure each announcement against an actual reference flight and price pickups again when their collection radius or placement changes.
- An offscreen marker competes for the same canvas space as hazard labels: reserve its actual painted bounds before placing labels. Simultaneous notices also need tier-aware priority, so a pickup cue cannot erase or duplicate an active hazard warning.
- Pickup reachability alone does not establish safety or a meaningful detour. Measure collect-box clearance over hazard motion, compare paired pilots for collection and extra crashes, and check the actual rendered token against sprite and building footprints over the full motion period.
- Art gates must be calibrated against the shipped references before judging candidates. A fixed vivid-colour cap rejected the existing warm yellow washer, and normalising texture to each sprite's drawn size made unrelated scales incomparable; measure explicit hue and content-normalised texture instead. Keep negative controls and candidate assets on the same gate functions.
- A sprite-sheet assembler must not infer subject count by cutting the raw image into the requested grid: a wrong grid can split one figure and conceal a missing subject. Detect subjects globally and test the wrong-count case.
