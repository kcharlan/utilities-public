# Architecture

`src/main.c` parses arguments through `src/cli/args.c`, then delegates to
`src/cli/run.c`. The release is a C17 executable; it does not invoke tests
or Python at runtime.

The pipeline is parse → scan/cache → metadata/corpus/workspaces →
catalog/priority/pricing → payload/page:

| Modules | Role |
| --- | --- |
| `src/parse/`, `src/model/` | Stream JSONL into log records, turns, messages, tools, links and usage observations. |
| `src/scan/`, `src/cache/` | Discover logs, reuse or reparse native cache entries, stage and commit cache updates. |
| `src/meta/` | Load Codex metadata through read-only SQLite connections. |
| `src/acct/` | Track token totals, classify rollouts and resolve inherited fork baselines. |
| `src/corpus/` | Assemble sessions, titles/status, subagent relationships and workspace aliases. |
| `src/price/` | Fetch/cache catalog, validate and record history, retain priority evidence, compose usage and dated costs. |
| `src/out/` | Serialize payload and embed it in the offline page. |
| `src/cli/`, `src/util/` | Coordinate lifecycle, progress, browser/summary, atomic I/O, events, Unicode and stable sort. |

Catalog work starts before scanning and joins before pricing. The CLI reads
ledger state and detects edits before appending newly observed rates; this
does not eliminate the concurrent read/replace race. Rendering precedes
cache commit. Cleanup joins catalog work before freeing shared resources.

`tools/embed.pl` embeds `assets/` into build-generated C. Page shell, CSS,
JavaScript, Martian Mono font subsets and their notice, public curated rate
seeds, and Unicode 17 pricing-property ranges ship in the executable.
Unicode 16 normalization/casing tables are committed in `src/gen/` and are
not regenerated by make. yyjson 0.13.0 is vendored in `vendor/yyjson/`.
Production includes retain minimal `src/testing/` support headers; release
test hooks are inactive unless compiled with `COLOPHON_TESTING`.

The fresh test harness independently checks synthetic behavior and retained
C units. The original captured-corpus parity/performance machinery is not
part of this project. See [development](development.md) for its validation
boundary and [third-party notices](../THIRD_PARTY.md) for provenance.

## Usage accounting rules

Long-context thresholds follow CodexBar `v0.74.1` (commit `7c08c0ae7`).
For a catalog model with `context_over_200k`, select the first positive
`context` tier whose rate presence and values match that lane. A non-null
`tier` on the lane itself prevents a match. Fall back to the documented
bundled threshold, then 200,000. Without that lane (or without a catalog
model), retain the bundled threshold. Decode every tier strictly, including
entries after a match; malformed tiers reject the model. Corrected curated
history uses 272,000 in existing entries so earlier usage is repriced rather
than receiving only a newly dated catalog correction.

Remaining differences from `v0.74.1`:

- Bundled threshold lookup uses the normalized requested model; upstream uses
  the normalized catalog id (`ModelsDevPricing.swift` L246–247 and
  `CostUsagePricing.swift` L65–67). Targets normally agree; native retains one
  bundled-row lookup.
- Ledger-record model selection remains native `model_at` in
  `src/price/compose.c`; upstream `handleRequestLedger` selects differently
  (`CostUsageScanner.swift` L4332–4336). This is outside this alignment's scope.
- Native has no ledger running-counted-total overflow guard; upstream does
  (`CostUsageScanner.swift` L4290–4297). This is outside this alignment's scope
  and separate from per-request numeric validation.
- Native does not port `rememberMirroredLegacyPricingKey`
  (`CostUsageScanner.swift` L4355), `ledgerLegacyPricingKeys` (L361, L4141), or
  `CostUsageScanner+TurnPerformance.swift`. Changed logs reparse from the
  beginning; incremental and turn-performance machinery is outside scope.
- Existing adaptations retain the [Explicit adaptations and approved
  differences table](../../colophon/docs/token_rules.md#explicit-adaptations-and-approved-differences),
  except where a later alignment rule replaces an item. The per-turn primary
  rule in Spec §15 difference 1 remains until request pairing is aligned.

Python Colophon's existing 200,000 catalog fallback can append conflicting
entries to a shared runtime ledger. Use a separate `COLOPHON_HOME` for the
Python launcher, or retire it; this change does not migrate private ledgers.

Request-ledger acceptance follows CodexBar `v0.74.1`: require a nonempty
trimmed string thread id matching the NFC session identity. An optional
session id must be a nonempty trimmed string matching the file's trimmed
`session_meta.payload.session_id`, or the session identity when absent/blank.
Foreign ownership is silently skipped. Require a nonempty trimmed response
id, a valid timestamp, integral nonnegative input/output counts, and a thread
total covering input, cached input and output. Optional cached/reasoning counts
default to zero only when absent; reject other types, fractions, nonfinite
values, values whose double representation reaches 2^63, cached > input,
reasoning > output, and input + output overflow. Invalid owned records produce
one aggregate `usage_record_rejected` event. Valid responses deduplicate by NFC
trimmed response id. Keep a turn total only when valid and covering usage.
Ledger cached input uses `cached_input_tokens` only; snapshot rows retain their
existing cache-read alias rule.

Turn identifiers select the first nonempty string `turn_id`, `turnId`, `id`
from payload, then info. A ledger without an explicit turn takes the latest
preceding `task_started` turn in the same file, then the latest nonempty
`turn_context` turn. A started event without a turn clears the started fallback;
blank or truncated contexts leave the active context unchanged. Native cache
format `native:1:2` retains request session ids, ledger totals and context turns.
